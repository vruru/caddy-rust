# Scoped native client work retirement

An outgoing scope has two fences. Existing `wait()` retains the original complete ownership contract, including metadata-only errors and actual IO. On the tested native Unix path, `close()` followed by `wait_physical()` waits for tracked connector work, owned blocking DNS jobs, unconsumed address/connection results and actual returned scoped IO. Keeping a completed error and its original metadata allowance does not keep the physical fence pending. It still keeps the original ownership fence pending until the error is dropped.

A concrete ConnectionLease carries the physical token separately from its metadata Life. DNS jobs and successful iterators retain the complete lease; only a joined error result can consume it into a metadata-only error holder. A queued/running connector hands the same lease to the existing TLS executor. The tracked executor envelope destroys its future, running permit, proof state and executor token before the connector receipt. Scoped IO destroys its inner IO before its lifetime lease. Scope admission creates tokens under the existing close locks after prepayment; scope cancellation and wakeups happen outside those locks.

The new token/control layouts use the existing finite connection subtype and parent pools. Scope/parent cancellation-tree high-water bounds are recomputed from the updated minimum connection geometry. The additional tracker reserve follows the pinned tokio-util 0.7.20 AtomicUsize/Notify/Arc layout; it adds no execution lane, independent payload pool, fixed CPU limit or unbounded lookup queue. Metadata remains admitted through its actual last owner.

Local components exercise an actual ACME client with an owned system lookup held after getaddrinfo while the native answer list remains live, caller abort and join, independent-scope progress, retained iterators/errors and pressure recovery. Actual TLS components exercise a strict verifier blocked inside its real call, an unconsumed returned connection, idle IO, interrupted response, master abandonment and preserved readiness/call/scheduler error sources. These use macOS and Linux ARM64 all-CPU and one-CPU profiles. The post-getaddrinfo hold does not simulate stalling libc internally.

This is a prerequisite, not issuer timeout failover. Configured issuers still share cached clients and pools; an operation-owned wire/pool, first directory/account setup isolation, legacy-order recovery and exact per-leg drain must be integrated and tested before a hanging issuer may safely advance to another. Non-Unix/default Gai work is not given this new Unix fence contract. Standalone public constructor behavior and complete issuer/PKIX compatibility are not claimed changed.
