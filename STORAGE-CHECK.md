# Automatic-certificate storage checks

The TLS application's `disable_storage_check` switch controls an optional read/write probe for business certificate automation. The default is false, so the probe is enabled. Admin identity management retains its independent default check. This switch does not disable real certificate/account/checkpoint writes, storage leases, recovery fences, private-key checks, certificate validation, revocation or key-compromise rules.

A complete healthy stored certificate can be returned without a probe. Manual certificate loading, read-only cache inspection and ARI-only refresh do not run it. Before actual new issuance, or recovery of an unfinished issuance candidate that can save/claim material, the current invocation performs a probe of its selected certificate **data** root. One invocation shares the result across issuer fallback and test-CA/primary stages. A later actual retry invocation checks again; there is no process-global writable-storage cache.

The probe writes 10KiB of random data to an exclusive random key, loads at most that size and compares all bytes, then deletes only its own file. Readback allocation is bounded before growth. It uses the existing storage worker admission and certificate temporary-memory budget. Receipt bookkeeping retains the actual open inode; cleanup verifies device/inode through the fixed directory descriptor and refuses to delete a replacement file. It also distinguishes an owned atomic rename followed by failed directory synchronization from a no-replace collision.

Normal completion includes cleanup. A delete failure is a real error even if write/read succeeded; simultaneous operation and cleanup errors retain the primary cause and report the secondary error. A cancelled live waiter joins the real worker. A dropped waiter transfers its actual join to existing tracked cleanup; the worker, join and cleanup retain the same admitted credit through their actual lifetimes. If the caller runtime is already gone, an adopted future may itself be dropped: worker registration still covers physical IO, but this is not a claim that its join was observed or that a shared blocking-pool OS thread was individually joined. A permanently blocked kernel operation cannot be made immediately cancellable. Process crash or SIGKILL can leave a test artifact; this option adds no orphan/expiry sweep or cleaning policy.

The check runs within the existing name/issuance lease. CertMagic 0.25.6 performs its check before acquiring that lease. Native retains its existing fencing order and may make existing cached directory/ARI discovery before determining that new issuance is needed; no new account/order or production candidate may precede the required check.

Two pinned-baseline defects are deliberately corrected. Caddy 2.11.7 forwards its TLS-app flag to the manual-loader configuration but omits it from the actual automation-policy configuration; Native makes the business automation field effective. CertMagic's deferred delete assigns a local variable in a function with an unnamed return, so a cleanup error can be lost; Native returns it. These are functional corrections, not a claim of identical original failure behavior. Other storage cleaning controls remain outside this change.
